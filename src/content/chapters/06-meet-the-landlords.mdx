Each of the three big cloud providers offers all four kinds of home from Chapter 5. The names are different and some details are different. Some providers suit some companies better than others. First, here is a table to translate the names. Then we look at each provider.

<Sketch name="ch06-1" />

| Kind of home | AWS | Microsoft Azure | Google Cloud |
|---|---|---|---|
| Managed agent runtime | Bedrock AgentCore Runtime | Foundry Hosted Agents | Agent Runtime (formerly Vertex AI Agent Engine) |
| Console agents | Bedrock Agents | Foundry prompt-based agents | Agent Designer, in the Gemini Enterprise app |
| Functions | Lambda | Azure Functions | Cloud Run functions |
| Serverless containers | ECS on Fargate | Container Apps | Cloud Run |
| Classic web hosting | Not covered here | App Service | Not covered here |
| Kubernetes | EKS | AKS | GKE |

<Sticky color="yellow" tilt="left" width="70%">

The biggest reason for choosing a provider is usually not the agent. It is **which cloud your company already uses**. Your contracts, security setup, data and staff skills are already there.

</Sticky>

<Takeaways>

- Every provider offers every kind of home, with different names.
- The cloud you already use is usually the deciding factor.
- Each provider's agent runtime works best with that provider's own sign-in, security and AI tools.
- Containers and Kubernetes are the easiest to move between providers.

</Takeaways>
