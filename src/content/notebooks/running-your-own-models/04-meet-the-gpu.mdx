A normal computer chip (a CPU) is like a few very skilled chefs. A **GPU** is like thousands of kitchen helpers who each do one simple job, all at the same time. Running a model takes billions of simple multiplications for every token, so a GPU does it far faster than a CPU.

## Memory is the first question

When you pick a GPU for a model, the first question is not speed. It is **memory**. The weights must be in the GPU's own memory, and the KV cache from Chapter 3 needs room next to them.

<Sketch name="rm-ch04-1" />

Think of GPU memory as counter space. The recipe (the weights) takes a fixed part. The notes for every order (the KV cache) take the rest. If the recipe fills the whole counter, you can't cook anything.

Serving software such as vLLM takes a share of GPU memory when it starts. By default, vLLM uses 92% of it. It loads the weights, keeps some room for its own work, and gives everything else to the KV cache.

## Will it fit?

A simple way to check:

1. Work out the weights: parameters × bytes per parameter (Chapter 2).
2. Take about 90% of the GPU memory. That is roughly what the serving software can use.
3. Subtract the weights. What is left is for the KV cache. If it is nothing, or very little, the model does not fit in practice.

For example: an 8B model in BF16 on an L4. The weights are about 16 GB. 90% of 24 GB is about 21.6 GB. That leaves about 5.6 GB for the KV cache. It fits, but with room for only a modest number of conversations at once.

## Making the model smaller: quantization

**Quantization** means storing the weights with fewer bits: 8 or 4 instead of 16. The model takes less memory and often runs faster.

- **FP8** halves the memory compared with BF16. Newer GPUs such as the L4, L40S and H100 have built-in support for FP8 math. Older ones such as the A100 and A10G do not, so FP8 helps them less.
- **INT4** takes about a quarter of the memory of BF16. More of the model's quality can be lost.

Many model makers publish ready-made FP8 or 4-bit versions of their models. Use those when you can, and test the answers on your own tasks.

<Careful>

**Quantization can quietly change answers.** A 4-bit model may be fine for chat but worse at following strict tool-call formats. Botley books real flights. Test the quantized model on Botley's real tasks before it goes live.

</Careful>

## When one GPU is not enough

A 70B model in BF16 needs about 140 GB for its weights alone. Only the B200 can hold that on one GPU, and it is rare and costly. The usual answer is to split the model across several GPUs in the same machine. This is called **tensor parallelism**: each GPU holds part of every layer, and they work on each token together. In vLLM, you set it with `--tensor-parallel-size`.

For example, NVIDIA's own tests run Llama 3.3 70B in FP8 (about 70 GB of weights) on 2 or 4 H100 GPUs.

## Not only NVIDIA

- **Google TPUs** are Google's own chips: TPU v5e (16 GB per chip), v6e “Trillium” (32 GB) and TPU7x “Ironwood” (192 GiB), which became generally available on 31 March 2026.
- **AWS Inferentia2** (32 GB per chip) and **Trainium** are Amazon's own chips.

They can be cheaper for some models, but they need software built for them. Check that your model and serving tool support them before you choose them.

<Careful>

**New cloud accounts usually can't start GPU machines at all.** On AWS, the default quota for G and P instances (the GPU families) is 0. On Google Cloud, free trial accounts can't use GPUs, and you need GPU quota for your region. On Azure, quota is set per machine family. Request more quota early. It can take days, and popular GPUs can be hard to get in some regions.

</Careful>

<NoSillyQuestions>

<QA q={"Should I just get the biggest GPU?"}>

No. A big GPU running a small model is mostly idle, and you pay for every hour. Pick the smallest GPU that fits your model with enough room for the KV cache, then measure.

</QA>

<QA q={"Can I use Spot machines for a live agent?"}>

Only with care. The cloud can take a Spot machine back with very little warning, and getting a new GPU can take minutes. Spot works better for batch jobs, or as extra capacity next to normal machines.

</QA>

<QA q={"Why is GPU memory such a big deal? My laptop has 32 GB of RAM."}>

The model must be in the GPU's own memory, which is separate from the computer's normal RAM. GPU memory is much faster, and much more expensive.

</QA>

</NoSillyQuestions>

<Takeaways>

- GPU memory is the first thing to check. Weights and KV cache must both fit.
- vLLM uses 92% of GPU memory by default and gives what is left after the weights to the KV cache.
- GPUs range from 24 GB (L4, A10G) to about 180 GB (B200). Prices range from under $1 to over $100 per hour per machine.
- Quantization (FP8, INT4) shrinks models. Test the quality before you rely on it.
- Big models are split across several GPUs with tensor parallelism.
- Ask for GPU quota early. New accounts often start with none.

</Takeaways>
