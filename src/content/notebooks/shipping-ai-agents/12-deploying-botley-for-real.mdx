## Before you start

- [ ] A cloud account, and permission to create resources in it.
- [ ] The cloud's own command-line tool installed and signed in (`aws`, `az` or `gcloud`).
- [ ] Access to the AI model your agent uses, turned on in that cloud.
- [ ] Botley's code split into a brain and a small adapter (Chapter 3), and tested on your laptop.
- [ ] No passwords or keys in the code (Chapter 4).

<Careful>

**Commands change.** These cloud tools are new and change often. The commands below are correct as of October 2026. Before you start, run each tool's `--help` and check its latest documents.

</Careful>

## After it is live

| You want to... | What to do |
|---|---|
| Change Botley | Change the code or instructions, test it locally, run your evals, then run the deploy command again. Each deploy creates a new version. |
| Go back | Point traffic back to the last good version. Keep the old version until the new one has proved itself. |
| Stop paying | Delete what you don't need. Unused memory stores, registries and test agents still cost money. |
| Do it every time, safely | Put these same commands into an automatic CI/CD line with an eval gate (Chapter 7). |

<NoSillyQuestions>

<QA q={"Why does every cloud need a “blueprint” tool like CDK, Bicep or Terraform?"}>

A deployed agent is not one thing. It is a runtime, a memory store, permissions, logs and more. Writing them down as code means you can rebuild the same setup any time, and see exactly what changed.

</QA>

<QA q={"Do I have to use these agent CLIs?"}>

No. They are shortcuts. Underneath, they call the normal cloud APIs and blueprints. Big teams often call those directly from their CI/CD line.

</QA>

<QA q={"Why test locally first?"}>

It is faster and free. Most mistakes, like the wrong port or a missing library, show up on your laptop in seconds instead of after a ten-minute deploy.

</QA>

<QA q={"How do I know it really worked?"}>

Send a test message, check the health and logs, and run your eval set against the live version. A deploy that “finished” is not the same as a deploy that works.

</QA>

<Takeaways>

- Every deploy command reads settings, packs the code, builds cloud parts from a blueprint, and starts the new version.
- AWS uses the AgentCore CLI, Azure uses azd, and Google uses the agents CLI (for ADK agents).
- Always try the agent locally before deploying.
- Check the live agent with a test message, logs and evals.
- Each deploy is a new version. Keep the old one until the new one is proven.

</Takeaways>
