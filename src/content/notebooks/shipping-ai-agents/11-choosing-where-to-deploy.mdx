## Six questions every company should ask

| Question | Why it matters |
|---|---|
| Which cloud do we already use? | Staying there lets you reuse your contracts, security setup, data and skills. This usually decides the provider. |
| Who does the agent act for? | If it acts for individual staff or customers, you need sign-in and access rights for each person. Managed runtimes include this. Other homes need extra work. |
| How long does one task take? | Tasks of a few seconds suit functions. Long chats or long jobs suit managed runtimes or containers. |
| How does usage change? | If usage is low or goes up and down, homes that scale to zero save money. If it is busy all the time, always-on containers or Kubernetes may cost less. |
| How tied to one provider can we be? | Console agents and managed runtimes tie you to one provider. Containers and Kubernetes are easier to move. |
| What can our team look after? | Kubernetes needs a dedicated team. Console agents and managed runtimes need the fewest people to run. |

- Whose identity does the agent use?

- no evals and no traces
- no way to go back to the old version
- no answer about prompt injection

<Takeaways>

- Start from your situation, not from a product name.
- The cloud you already use usually picks the provider. The agent's needs pick the home.
- Ask about separate conversations, identity, records, release checks and spending limits.
- Most companies use several homes at the same time.

</Takeaways>
